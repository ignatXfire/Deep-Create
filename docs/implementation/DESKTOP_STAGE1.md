# Desktop/UI: actual cut of stage 1

Date: 2026-09-09. Basis: Document 13, C-14 of Document 19 and Stage 1 of Document 20.

## What's created

Separate package `crates/dc-desktop` (Tauri 2) and view `ui` (React / strict TypeScript). The application identity is `com.deepcreate.desktop`. The only applied native command `application_info` returns exactly `version` and `buildStage: "empty_shell"`. The version is taken from `CARGO_PKG_VERSION` during compilation, and not from the environment of the running process. The command does not read files, clocks, environments, secrets, Hermes state, or change state; does not create an event.

The page in Russian directly says: the application does not yet know how to perform work. There is no model, research demo, progress, start button, fictitious results or saved user data. In a browser without Tauri, it shows a "version not verified" refusal, not a fictitious version. Invalid native response form, additional fields, and unknown stage are also rejected.

The five protected executive roles from Document 13 are **not implemented** here. There are no empty future process packages, work control protocol, storage, mediator, gatekeeper, model connections, bridges, or owner confirmations.

## Access surface and rule source

Regular custom Tauri commands, registered via `invoke_handler`, are available to application windows by default. Therefore, `build.rs` explicitly sets `AppManifest::commands(&["application_info"])`, and `tauri.conf.json` selects the only capability `version-page`. It contains only `allow-application-info`, window `main`, `local: true`; There is no remote context. Reason: [official contract capabilities Tauri](https://v2.tauri.app/security/capabilities/) and [AppManifest::commands](https://docs.rs/tauri-build/2.6.3/tauri_build/struct.AppManifest.html).

Plugins fs, shell, http, sql, opener, store and others are not connected. No `core:default` and separate core permissions. Dynamic ACL extension is not included in Tauri's own features list. This is a description of application permissions, and not a statement about the absence of internal transport commands of Tauri itself.

CSP sets `default-src 'none'`, only built-in script/style/img/font and `connect-src ipc: http://ipc.localhost` for native IPC. No external domain permissions, wildcard, unsafe-inline, unsafe-eval, devCsp, or CSP disabling. Asset protocol is disabled; no devUrl. Reason: [official CSP agreement Tauri](https://v2.tauri.app/security/csp/). Native window additionally rejects external navigation, new windows and file downloads; drag-and-drop and devtools are disabled. Only embedded page `/` or `/index.html` of local Tauri origin is allowed.

This is not proof of Windows administrator isolation, a WebView2 vulnerability, a compromised dependency, or arbitrary malicious Rust. Tauri/WebView2 create their own profile service files; disallowing direct UI access does not mean that the shell process does not use the OS file system at all.

## Native tests and the general verification boundary

In `crates/dc-desktop/src/main.rs` tests are prepared through the real Tauri IPC manager with `MockRuntime` and `generate_context!()`:

1. The metadata response only has two expected fields and an immutable stage.
2. Local window `main` reads `application_info`.
3. A window without a selected capability receives an ACL denial even to the registered `application_info` - default-deny check.
4. Remote origin and unspecified core/fs/shell/http/sql/owner-decision/unknown commands receive an ACL refusal.
5. Valid local URLs and prohibited external URLs, file/data, other path, query, credentials, spoofed host and port are checked.

When viewing tests, a logical gap has been eliminated: `is_err()` alone is not enough, since an argument error can be mistaken for a prohibition. Negative IPC tests now require Tauri message `not allowed`. Static CSP/dependency/plugin tests also use exact equality rather than partial matches that allow extra fields.

After preparing the UI slice, the general check resulted in successful `cargo test` for desktop - **5/5** - and `cargo build`. This is a confirmation of the IPC dispatcher and compiled ACL in a mock-runtime, not a real WebView2, a CSP in a running window, or a pure system without Hermes. The actual native launch is checked separately; the final status and native assembly proofs belong to the general implementation registry.

## Automatic architectural verification

Added `tools/check-architecture.mjs` and `tools/tests/check-architecture.test.mjs`, without new runtime dependencies.

- Direct dependency check reads `cargo metadata --format-version 1 --no-deps --locked --offline`. For existing packages, the specific purpose of each dependency, allowed kind (normal/build/dev), source, requirement version, features, and default-features are listed. A new package, dependency, path/git substitution, renaming or features extension requires an explicit contract edit. Since 2026-09-11 the third package `dc-protocol` has been registered with a single exact local connection to `dc-domain`; the new boundary and current results are described in `PROTOCOL_CODEC.md` and `STATUS.md`.
- C-01 is checked by a lexical pass through its own Rust: direct `std::fs/net/time/env/process/thread/os/io`, grouped `use`, raw identifiers, import of the entire standard library, external include/env/output macros, `extern` and module redirection via `#[path]` are detected.
- Explicit `unsafe` is prohibited in native code outside of the future registered adapter `dc-windows`; Until such a package is included in the agreement, it itself is considered unregistered. Strings, raw strings and comments are not considered executable code. I/O test harness is not advertised I/O C-01; unsafe is still checked in the test code. Inert files `tests/fixtures` are excluded from crawling, `src/fixtures` are not excluded.
- **30/30 artificial selftests passed**, including new package, domain→store/network, desktop→store, unsafe, incomplete metadata, source/version/features change and code-like lines.
- A separate pass through the actual Rust sources `dc-domain` and `dc-desktop` returned an empty list of violations. The full metadata pass is passed to the general assembly check; its result is not replaced by the result of selftests.

This is **not a complete Rust AST analysis**, not macro expansion, not a proof of the absence of all indirect I/O methods, not an audit of transitive dependencies, nor a proof of OS isolation. Compiler unsafes and bounds tests complement this limited linter.

```powershell
node --test tools/tests/check-architecture.test.mjs
node tools/check-architecture.mjs
```

npm exec --yes --package=pnpm@12.3.4 -- pnpm install --frozen-lockfile --offline

`desktop:dev` and `desktop:build` are defined separately; both build embedded UI files first. `desktop:build` does not create an installer yet. Checking the full CLI path, common Cargo.lock, EXE, and standalone launch is a general build check, not a UI check.
