# Deep Create: research overview

Deep Create explores an evidence-carrying feedback loop for long-running LLM-agent work. Its central question is what a system should retain, invalidate, and feed into the next attempt after an error or change—without treating a model's text as an authoritative state transition.

The intended cycle is context selection, proposed work, artifact verification, recorded evidence and feedback, graph revision, and a newly selected context. Its efficiency hypothesis is selective reuse: preserve applicable progress, repair the affected part, and carry the reason for the correction forward. More cycles or more agents do not establish a benefit by themselves. The mechanism and a concrete domain-test example are explained in [The next attempt should inherit evidence](CYCLIC_WORK.md), with an [evidence map](EVIDENCE_MAP.md) and a [fair evaluation protocol](EVALUATION_PROTOCOL.md).

The intended process begins with an owner's objective and acceptance criteria. The controller records obligations and a versioned work graph. A worker receives relevant context and a scoped action surface. It produces an artifact and provenance. Independent verification evaluates the actual criteria and current dependencies before admission and durable commit. An uncertain external outcome requires reconciliation before another attempt.

The technical constitution specifies a standalone Windows application. Hermes was used in external development workflows, but that does not make those workflows capabilities of Deep Create itself. Rust carries domain/native rules, SQLite provides local persistence, Tauri hosts the desktop shell, and TypeScript/React provides the interface. The workspace contains nine Rust packages. Their presence does not establish a complete integrated runtime.

The research materials make several distinctions explicit: a documented contract is different from existing code; existing code is different from a connected caller path; a passing test is different from a verified complete capability. Confidence does not create permission. Compression is a derived context projection with provenance rather than authority to destroy original evidence. A result must be tied to its work unit, attempt, dependency versions, artifact, and observed cost.

The October 1 independent audit records substantial implementation together with important defects. Its selected Rust tests passed, while three UI tests failed. Its probes include successful reproduction of defects. Open questions concern durable desktop command/result transitions, meaningful machine verification, identifier consistency, dependencies after failure, isolation, retry behavior, and atomic accounting. These historical findings must be checked against exact source revisions before a future fix is accepted.

The public package includes the primary implementation, full technical documentation, tests, audit snapshots/probes, and separate development-organization research. It excludes raw private conversations, original Git metadata, runtime credentials/databases, caches, and machine-specific operational state. Translation and redaction change the public bytes, so original evidence hashes remain historical references rather than current integrity proofs.

This material may be useful to researchers studying persistent agent workflows, revocation, acceptance boundaries, provenance, and failure recovery. No novelty benchmark, superiority claim, readiness percentage, complete autonomy, or production-security guarantee is asserted.
